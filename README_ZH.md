# 提示词预览与历史

为 DSH 原生输入框增加两个能力：回答完整结束后建议下一句用户提示词，以及用 ↑/↓ 回顾并恢复最近的提示词。

[English](README.md)

## 特性

- **下一句预览。** 一轮回答完整结束后，输入框为空且会话空闲时，用当前会话模型生成一条简短的、用户视角的下一句消息。
- **只建议，不发送。** 建议只是预览。Tab 把它填入草稿，Esc 忽略；插件不会自动发送，也不会在后台改写草稿。
- **复用而不重复调用模型。** 为某一轮生成的建议会缓存。输入、粘贴、输入法组合和历史回顾只会隐藏它；清空草稿后恢复同一条建议，不再调用模型。
- **提示词历史。** ↑ 回顾更早的提示词，↓ 返回较新的提示词，翻过最新一条后恢复原草稿。输入前缀会过滤历史，开始编辑即退出回顾。
- **原生布局。** 预览占用输入框已有的浮层位置。只有建议就绪时输入卡片才扩展，真实编辑器继续负责焦点、光标和输入法；没有建议时输入框保持原样，生成过程中仍显示原生占位文字。

## 兼容性

- DSH `>=0.2.1-rc.2 <0.3.0`，Node.js >= 22。
- 启用本插件前先停用 `dsh-prompt-history`。两者同时运行会产生重复的键盘监听和重叠的预览。
- 不需要额外模型配置。预览生成使用会话已选模型，并消耗该模型的额度。

## 安装

在 DSH 左侧栏打开 **插件 → 添加插件 → 安装第三方插件**，填入：

```text
https://github.com/catwithoutear/dsh-prompt-assist.git
```

也可以通过插件管理器安装本地检出目录。包名为 `@catwithoutear/dsh-prompt-assist`，显示名称为**提示词预览与历史**。

更新已安装版本时：执行 `npm run build`，在插件管理器中重新安装或应用源码，Host 改动后重启 DSH，Client 改动后刷新页面。已加载的 Host 模块必须通过重启替换，仅刷新页面不足以加载新代码。从旧 `@local/dsh-prompt-assist` 升级时，先移除旧插件条目并安装 `@catwithoutear/dsh-prompt-assist`，确认新包已安装后再重启 DSH。

## 使用

1. 等待一轮回答完整结束。会话空闲且没有排队输入时，可见的空输入框会显示灰色建议，并提示 `Tab 采纳 · Esc 忽略`。
2. 按 **Tab** 把建议填入草稿；不会发送。
3. 按 **Esc** 忽略本轮建议。
4. 按 **↑** 回顾较早的提示词，按 **↓** 返回较新的提示词。翻过最新一条会恢复最初草稿；输入框已有前缀时只回顾匹配项。
5. 输入、粘贴、输入法组合或打开历史会隐藏当前建议；清空草稿后，缓存过的建议会恢复。

会话运行中、已附加文件或图片、输入框不在普通编辑状态时，不显示建议。历史只恢复文本，不会重建早前提示词中的附件。

## 行为与保证

- **触发资格。** 只在 `completed` 的轮次结束后请求建议，且本轮最后一条助手消息有文本、未中断、不含工具调用；会话必须空闲且没有排队输入。工具活动、消息渲染和输入框聚焦都不会触发。
- **模型选择。** 使用会话的 `modelSelection.next` 或 `lastUsed`，最后回退到会话请求头；不回退全局默认模型，并保持相同 provider 与 model。模型支持时使用最低推理强度，否则沿用会话已选强度。单次输出上限 2048 tokens，超时 60 秒。
- **上下文。** 只发送最近 8 条用户与助手文本，保留角色区分；用户文本截断到最后 2400 字符，助手文本截断到 3200 字符，工具输出、思维过程和系统提示都被排除。
- **过滤。** 系统提示要求输出少于 160 字符。空串、超过 200 字符、含换行、以 Markdown/列表/角色前缀开头、或带有助手口吻的建议会被丢弃。失败与空结果不会自动重试；超时按 stale 处理，可能在输入框下次满足条件时重新请求。
- **历史。** 最多取当前会话最近 200 条真人文本消息，连续重复项会合并。历史只恢复文本，并从会话日志重建，刷新页面后仍可回顾。
- **安全。** 不做全局浮层、固定定位、DOM 注入、聊天 DOM 监听或轮询。预览是输入框浮层槽位中的状态元素，布局样式限定在插件范围内，并随组件卸载移除。

## 开发

```sh
npm ci
npm run build       # 从 src/ 重新生成 lib/client.js
npm test            # node:test 测试
npm run check       # 语法检查 src/index.js 与 lib/client.js
npm pack --dry-run  # 查看分发文件清单
```

只修改 `src/` 下的模块。`lib/client.js` 由 `build.mjs` 生成，不要手改。构建是幂等的：源码不变时产物逐字节一致。

## 测试

测试共 22 项，分布在三个文件：

- `test/core.test.js` — 会话 fold、触发资格、文案过滤、历史回顾、模型选择、wire 校验。
- `test/preview-state.test.js` — 候选缓存、可见性切换、取消、迟到结果、忽略与重试规则。
- `test/host.test.js` — 真实 Cordis 上下文中的 Host 服务，桩掉 agents、投影和 LLM 流。

测试覆盖纯逻辑、预览控制器和 `predict` 主路径；不覆盖插件的 `apply()` 注册、React 客户端组件、浏览器原生事件或实际布局几何，也不证明真实模型输出质量。浏览器与视觉验证未自动化。

## 限制

- 建议质量取决于当前模型。插件只过滤明显无效的输出，无法保证下一句一定有用。
- 生成失败或结果为空时本轮不显示建议，也不会重试；超时按 stale 处理，可在下次满足条件时重新请求。
- 布局兼容性依赖 DSH 输入框内部实现（浮层槽位、编辑器状态和 data 属性）。升级 DSH 后需要重新核对输入框行为。
- 没有设置页面、侧聊、剪贴板功能、补全或第二套历史存储。
