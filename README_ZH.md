# 提示词预览与历史

为 DSH 原生输入框增加提示词写作辅助：回答完整结束后建议下一句提示词、用 ↑/↓ 回顾历史、按草稿续写、一键把选中文本改写成意图清晰的指令。

[English](README.md)

## 特性

- **下一句预览。** 一轮回答完整结束后，输入框为空且会话空闲时，用当前会话模型（或你配置的辅助模型）生成一条简短的、用户视角的下一句消息。
- **可配置辅助模型。** 在 **设置 → 提示词助手** 中选择 DSH 已配置的 provider/model；不配置时沿用会话当前模型。插件不保存额外 API Key，也不会静默回退。
- **快捷键触发与自动预测。** `触发提示词预测`：空草稿请求下一句，非空草稿请求续写；`切换自动提示词预测`：打开/关闭整轮完成后的自动建议（默认开启，持久化）。
- **自定义快捷键。** 两个命令都可在 **设置 → 通用 → 快捷键** 中录制、改键、恢复默认；默认键冲突时插件仍可加载，并提示你手动指定。
- **草稿续写。** 输入框已有内容时，按触发快捷键在光标处请求续写；输入框内、编辑器下方显示预览面板，Tab 插入、Esc 忽略，不自动发送。
- **一键优化。** 选中文本（无选区时整段草稿）后按输入框工具行的 **优化** 按钮，把指令改写成目标、范围与约束都明确的版本，不替用户增加要求；结果先预览，确认后替换，可撤销。存在阻塞歧义时只显示待确认问题，不替换。**设置 → 提示词助手 → 优化策略** 默认 **忠实扩写**（调整用词、补出草稿已蕴含的细节），也可切换为 **澄清优化**（只消除歧义）；两者都不会新增草稿没有的目标、验收标准或技术选型。
- **只建议，不发送。** 所有结果都只是预览；只有 Tab/“应用”才写入草稿，插件不会自动发送或提交。
- **原生布局。** 下一句预览占用输入框已有浮层位置；续写/优化使用输入框卡片内、编辑器下方、工具行上方的同一块预览区，不注入编辑器 DOM。
- **提示词历史。** ↑ 回顾更早的提示词，↓ 返回较新的提示词，翻过最新一条后恢复原草稿；输入前缀会过滤历史。

## 兼容性

- DSH `>=0.2.1-rc.3 <0.2.2-alpha.0 || >=0.2.2-alpha.2 <0.2.3-0`（已验证：`0.2.1-rc.3`、`0.2.1-rc.4`、`0.2.2-alpha.2`），Node.js >= 22。alpha 版本的 Docker 验证使用 Node 24。
- 已验证的精确 DSH 版本列在 [`verification/dsh-versions.json`](https://github.com/catwithoutear/dsh-prompt-assist/blob/main/verification/dsh-versions.json)，由 [`verification/`](https://github.com/catwithoutear/dsh-prompt-assist/blob/main/verification/README.md) 实际执行。`engines.dsh` 范围与该列表必须保持同步；范围内更新的 DSH 版本只有在矩阵通过后才算支持。
- 启用本插件前先停用 `dsh-prompt-history`。两者同时运行会产生重复的键盘监听和重叠的预览。
- 默认使用会话已选模型并消耗该模型额度；配置辅助模型后消耗所选模型额度。插件本身不新增凭据。
- 快捷键复用 DSH 原生注册与持久化。DSH 对 **web** 只允许 `Ctrl+/`、`Ctrl+Shift+,`、`Ctrl+Shift+.` 三个组合；`Ctrl+/` 属于快捷键页、`Ctrl+Shift+.` 属于可选的 inspector 插件，因此手动触发默认 `Ctrl+Shift+,`，自动预测开关在 web 上默认不绑定（可在 **设置 → 通用 → 快捷键** 手动指定）。桌面端不受此限，默认 `Primary+Alt+J` / `Primary+Alt+K`（macOS 上为 Cmd+Option）。

## 安装

在 DSH 左侧栏打开 **插件 → 添加插件 → 安装第三方插件**，填入：

```text
https://github.com/catwithoutear/dsh-prompt-assist.git
```

也可以通过插件管理器安装本地检出目录。包名为 `@catwithoutear/dsh-prompt-assist`，显示名称为**提示词预览与历史**。

更新已安装版本时：执行 `npm run build`，在插件管理器中重新安装或应用源码，Host 改动后重启 DSH，Client 改动后刷新页面。已加载的 Host 模块必须通过重启替换，仅刷新页面不足以加载新代码。从旧 `@local/dsh-prompt-assist` 升级时，先移除旧插件条目并安装 `@catwithoutear/dsh-prompt-assist`，确认新包已安装后再重启 DSH。

## 使用

1. **下一句建议**：等待一轮回答完整结束。会话空闲且没有排队输入时，可见的空输入框会显示灰色建议，并提示 `Tab 采纳 · Esc 忽略`。
2. **手动触发**：聚焦输入框，按触发快捷键。草稿为空时请求下一句；光标前有非空文本且光标折叠时在光标处请求续写；光标前没有文字时会提示。
3. **续写**：结果显示在输入框卡片内，按 Tab 把续写插入当前光标；光标移动或草稿编辑后需要重新触发。
4. **一键优化**：选中要改写的文本（或把光标放在草稿中不选中），点击工具行 **优化**。结果在输入框卡片内预览：
   - `MODE: replace`：点 **应用** 替换选区（无选区时替换整段），或 **取消**；
   - `MODE: questions`：只显示待确认问题，补充草稿后再次点击优化。
5. **自动预测开关**：按切换快捷键或在设置页勾选；关闭后不自动请求，手动触发仍可用。
6. **历史**：按 ↑ 回顾较早的提示词，按 ↓ 返回较新的提示词。翻过最新一条会恢复最初草稿；输入框已有前缀时只回顾匹配项。

会话运行中、已附加文件或图片、输入框不在普通编辑状态时不显示建议；草稿含引用 chip 或引用文本时不能整段优化，与它们重叠的选区会被拒绝并保留提示，直到草稿被编辑；续写不受影响。历史只恢复文本，不会重建附件。

## 设置

**设置 → 提示词助手** 按 DSH 设置页的原生样式分区展示：

- **自动预测**：一行开关，控制整轮回答完成后是否自动生成下一句。默认开启。
- **辅助模型**：卡片内选择“跟随会话模型”或某个已配置的 provider/model；选择 provider 后可挑选具体模型，或恢复使用该 provider 的默认模型。保存后即时生效，不需要重启插件。
- **优化策略**：默认“忠实扩写”，调整用词并把草稿已经蕴含的细节写明；可切换为“澄清优化”只做最小歧义修复。两档都不会新增草稿没有的目标、验收标准或技术选型。
- **主题**：设置页跟随 DSH 的浅色/深色主题；下拉框自带描边，两种主题下都不会和卡片背景融在一起。
- **快捷键**：以按键徽章显示两个命令的当前绑定，未绑定时显示“未绑定”，并提示到 **设置 → 通用 → 快捷键** 修改。

## 行为与保证

- **触发资格。** 下一句预览只在 `completed` 的轮次结束后请求，且本轮最后一条助手消息有文本、未中断、不含工具调用；会话必须空闲且没有排队输入。续写只由快捷键手动触发。优化由按钮触发，不受轮次资格限制，但要求输入框处于普通编辑状态。
- **模型选择。** 默认使用会话实时的 `modelSelection.next` 或 `lastUsed`，不回退到会话请求头，因此“开始时没选模型、之后在会话里选了模型”能立即生效；完全没有选择时提示“会话还没有选择模型”，而不是误报辅助模型不可用。配置辅助模型后使用该路由，并在每次调用前校验。模型不可用时显示可操作错误，不静默回退。下一句/续写使用最低可用推理强度；优化不指定推理强度。
- **上下文与限制。** 下一句只发送最近 8 条用户与助手文本（用户 ≤2400、助手 ≤3200 字符）。续写发送最近对话加草稿前缀/后缀（前缀+后缀合计 ≤8000 字符，不含对话部分），输出 ≤160 字符单行。优化发送选区（≤6000 字符）和少量上下文（前后各 ≤800 字符），输出 replace ≤6000 字符、questions ≤2000 字符。超限、超时、空输出、非法格式都有明确错误。
- **过滤。** 下一句沿用原有系统提示与 200 字符过滤；续写与优化使用独立校验，拒绝助手口吻、UI 指令和空结果。优化结果必须符合 `MODE:` 协议。
- **写入与竞态。** 所有写入都经过 `inputActions` 的草稿版本校验：续写还要求当前光标位置与触发时一致；整段优化使用带版本的 `insertText`，不使用无版本保护的 `setDraft`。迟到结果、已取消请求、编辑后的预览都不会写入。
- **历史。** 最多取当前会话最近 200 条真人文本消息，连续重复项合并；历史从会话日志重建，刷新页面后仍可回顾。
- **安全。** 不做全局浮层、固定定位、DOM 注入、聊天 DOM 监听或轮询。预览只注册 DSH 槽位；Host 重新校验会话、轮次、模型路由和输入长度，客户端不能指定模型，也不能改变内置的优化契约。

## 开发

```sh
npm ci
npm run build       # 从 src/ 重新生成 lib/client.js
npm test            # node:test，当前 43 项
npm run check       # 语法检查 src/index.js 与 lib/client.js
npm pack --dry-run  # 查看分发文件清单
npm run verify:docker  # 对已验证的 DSH 版本执行 Docker + Playwright 检查
```

只修改 `src/` 下的模块。`lib/client.js` 由 `build.mjs` 生成，不要手改。构建是幂等的：源码不变时产物逐字节一致。

## 测试

测试共 43 项，分布在四个文件：

- `test/core.test.js` — 会话 fold、触发资格、文案过滤、路由解析、`MODE:` 解析、历史回顾、wire 校验。
- `test/preview-state.test.js` — 候选缓存、可见性切换、自动/手动触发、取消、迟到结果。
- `test/draft-assist.test.js` — 续写/优化预览状态机、单飞、迟到丢弃、错误与取消。
- `test/host.test.js` — 真实 Cordis 上下文中的 Host 服务，桩掉 agents、投影和 LLM 流。

测试覆盖纯逻辑、控制器与 Host 主路径；不覆盖插件的 `apply()` 注册、React 客户端组件、浏览器原生事件或实际布局几何，也不证明真实模型输出质量。`verification/` 中的 Docker 测试覆盖 web 端的核心流程（composer、下一句 overlay、续写、优化），使用确定性模型桩；不覆盖桌面外壳与真实模型行为。

## 限制

- 建议与优化质量取决于所选模型。插件只做结构与明显无效输出的过滤，无法保证结果一定可用。
- web 端只能使用 DSH 允许的三个组合，其中两个已被官方插件（快捷键页、可选 inspector）占用；桌面端可以任意录制。默认键冲突时用户需要到快捷键设置手动指定。
- 续写/优化预览位于输入框卡片内，实际布局、滚动与焦点行为依赖 DSH composer overlay 槽位；升级 DSH 后需要重新核对。
- 优化是自包含的：使用插件内置的澄清契约，不读取任何环境或仓库内容，因此不依赖已安装的技能。
- 没有侧聊、剪贴板、第二套历史存储或自建快捷键系统。
